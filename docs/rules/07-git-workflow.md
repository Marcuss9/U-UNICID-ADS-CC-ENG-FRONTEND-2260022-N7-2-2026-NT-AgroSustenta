# 07 — Git, branches e pull requests

**Obrigatório**
- Primeiro consulte o estado atual e as autorizações da tarefa.
- Não faça commit, push, crie PR, merge, tag, release, nem altere issues ou configurações sem autorização **explícita da respectiva ação**.
- Para implementação autorizada, prefira branch específica a partir da `main` atual. Não altere `main` diretamente salvo instrução expressa.
- Não reescreva histórico, force push nem inclua mudanças não relacionadas. Preserve trabalho preexistente e não resolva conflitos descartando alterações de terceiros.
- Faça commits com mensagens descritivas e coesas; valide antes de abrir PR, se autorizado.
- PRs devem conter objetivo, escopo dos arquivos, testes executados, limitações e pendências. Não faça merge automaticamente por ter criado o PR.
- Se a tarefa solicitar somente análise ou planejamento, mantenha o repositório integralmente inalterado.

**Verificação:** antes de PR, confira diff para assegurar ausência de alterações não solicitadas.
